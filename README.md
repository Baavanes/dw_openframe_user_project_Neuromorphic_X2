# Double Wide Openframe User Project

The **user project** for the double-wide sky130 openframe. This repo follows the
`openframe_user_project` structure: you build your design inside the user-area
wrapper `double_wide_openframe_project_wrapper`, harden it with **LibreLane 3**,
then cell-swap the hardened GDS into the padframe.

The **padframe / harness** (the caravel analog) lives in the sibling repo
**`../dw_openframe`**: it generates the pad ring, the empty wrapper pin template,
and performs the final `make integrate` cell-swap.

## User area

- User area (`double_wide_openframe_project_wrapper`): **6754.63 x 4766.63 um**.
- **59 GPIOs** (vs openframe's 44): West 14, East 15, North 18, South 12.
- Boundary interface (openframe-style, all `[58:0]` vectors):
  `gpio_in`, `gpio_in_h`, `gpio_out`, `gpio_oeb`, `gpio_inp_dis`,
  `gpio_ib_mode_sel`, `gpio_vtrip_sel`, `gpio_slow_sel`, `gpio_holdover`,
  `gpio_analog_en`, `gpio_analog_sel`, `gpio_analog_pol`, `gpio_dm0/1/2`,
  `analog_io`, `analog_noesd_io`, plus the multi-domain power pins.

The physical pad each `gpio[*]` index maps to is documented in
`../dw_openframe/pad_summary.json`.

## Project structure

| Directory | Description |
| :--- | :--- |
| `openlane/` | LibreLane 3 hardening configs, one subdir per macro. |
| `openlane/double_wide_openframe_project_wrapper/` | Wrapper config + fixed pin template (`pin_template.def`). |
| `verilog/rtl/` | Source Verilog for your design. |
| `verilog/dv/` | Design verification testbenches. |
| `verilog/gl/` | Gate-level netlists (generated after hardening). |
| `def/ gds/ lef/ lib/ sdc/ signoff/ spef/` | Hardened output views (generated by `make harden`). |

## Development flow

```bash
# 0. one-time: PDK
make enable-pdk

# 1. put your design in verilog/rtl/double_wide_openframe_project_wrapper.v
#    (keep the module name and port list identical to the template)

# 2. harden the wrapper -> views saved into gds/ lef/ def/ ... at the repo root
nix develop --command make harden

# 3. (in ../dw_openframe) cell-swap your hardened GDS into the padframe frame
cd ../dw_openframe
nix develop --command make integrate \
    USER_GDS=../dw_openframe_user_project/gds/double_wide_openframe_project_wrapper.gds
```

## Important notes

- **Keep the port list identical** to the empty template so the hardened block
  cell-swaps cleanly into the frame.
- The wrapper is hardened against the fixed
  `openlane/double_wide_openframe_project_wrapper/pin_template.def` (shipped from
  the padframe generator), so the boundary pins line up with the pad ring. If the
  padframe is regenerated (`make pads` in `../dw_openframe`), refresh this file
  from `../dw_openframe/librelane/wrapper/pin_template.def`.
- Connect your design to power using the wrapper's `vccd1`/`vssd1` (and other
  domain) pins.

## Example design

The included `verilog/rtl/double_wide_openframe_project_wrapper.v` is a small
example: a 32-bit counter clocked from gpio 0, reset (active-low) from gpio 1,
driving its low bits out on gpios 2..33. Replace it with your own design.
